## Context

Сработавшее напоминание сигнализирует пользователю двумя UI-поверхностями, сходящимися в одном обработчике:
- Android-уведомление, построенное в `ReminderAlarmService.buildNotif()` — action-кнопки через `NotificationCompat.Builder.addAction`, каждая — `PendingIntent.getService()` на сам сервис с `action` и `EXTRA_SNOOZE_MIN`.
- In-app баннер `RingingBanner` в `RemindersScreen.kt`, вызывающий те же операции через `RemindViewModel`.

Обе поверхности сейчас жёстко используют «10 минут». Низкоуровневый механизм отсрочки (`ReminderAlarmService.snooze(minutes: Int)`, `Reminder.snoozedUntil`, `effectiveTrigger()`) уже параметризован по минутам и не сдвигает базу циклической серии (закреплено в bf8c5f9 и тесте `ReminderRecurrenceTest`) — это поведение не меняется, меняется только то, откуда берётся число минут.

Ограничение Android: система уведомлений отображает не более ~3 action-кнопок. Сейчас их 2 («Готово» + «Отложить 10 мин»); добавление ещё двух длительностей отсрочки без удаления кнопки превысило бы лимит.

## Goals / Non-Goals

**Goals:**
- Пользователь может отложить сработавшее напоминание на 10 минут, 1 час или 2 часа — как из уведомления, так и из in-app баннера.
- Поведение отсрочки для циклических напоминаний (не сдвигает базу серии) сохраняется без изменений.

**Non-Goals:**
- Произвольная (не из фиксированного списка) длительность отсрочки — не требуется.
- Изменение хранения/сериализации напоминаний (`ReminderStore`) — не требуется, формат `snoozedUntil` не меняется.
- Настройка списка длительностей пользователем (10/60/120 — фиксированные значения) — не требуется.

## Decisions

**Три отдельные кнопки в уведомлении вместо кнопки-меню.**
Альтернатива — оставить одну кнопку «Отложить», которая открывает диалог/меню выбора. Отклонено: раскрытие меню из уведомления требует either разворачивания activity (лишний переход поверх экрана блокировки) либо `RemoteViews`-кастомизации, что сложнее и менее надёжно, чем обычные `addAction`. Три статичные кнопки — стандартный паттерн для Android-уведомлений и не требуют открытия приложения.

**Кнопка «Готово» убирается из уведомления (BREAKING для UX).**
Из-за лимита в 3 action-кнопки нужно выбрать: 3 варианта отсрочки без «Готово», или 2 варианта отсрочки с «Готово». Выбрано первое — отсрочка чаще используется прямо с экрана блокировки/шторки, а «Готово» перекрывается тем, что уведомление и так остаётся, пока пользователь не откроет приложение и не отложит/не отредактирует напоминание; кнопка «Готово» переезжает в in-app баннер, который и так открывается по тапу на уведомление.

**Список длительностей — константа `listOf(10, 60, 120)`, без новой модели данных.**
Не вводится enum/data class для «пресетов отсрочки» — три числа используются напрямую в обоих местах (уведомление, баннер), т.к. это единственный текущий сценарий использования и добавление абстракции не оправдано.

## Risks / Trade-offs

- [Пользователи, привыкшие завершать напоминание прямо из шторки уведомлений одним тапом, потеряют этот путь] → Смягчается тем, что тап по самому уведомлению (не по кнопке) открывает приложение с баннером, где кнопка завершения доступна сразу.
- [Три кнопки с более длинными подписями («Отложить 1 час», «Отложить 2 часа») могут не помещаться по ширине на некоторых лончерах/языковых настройках] → Подписи короткие («10 мин», «1 час», «2 часа»), без слова «Отложить» в каждой кнопке, если система обрежет текст — тестируется на реальном устройстве перед релизом (см. `verify`/`run` skill).
